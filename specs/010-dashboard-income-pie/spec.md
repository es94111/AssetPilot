# Feature Specification: 儀表板收入分類圓餅圖

**Feature Branch**: `010-dashboard-income-pie`
**Created**: 2026-05-03
**Status**: Draft
**Input**: 儀表板 增新收入分類 圓餅圖；核心目標是讓使用者在儀表板可以直接看到收入分類，以圓餅圖顯示

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 查看本月收入來源分布 (Priority: P1)

使用者開啟儀表板後，除了現有的支出分類圓餅圖之外，還能看到一張「收入分類」圓餅圖，顯示本月各收入來源（如薪資、兼職、投資）的佔比。

**Why this priority**: 收入分類是財務健康的核心指標，與支出分類同等重要；使用者需要在同一頁面同時掌握收入與支出的組成，才能做出有效的財務決策。

**Independent Test**: 在儀表板上看到標題為「收入分類」的圓餅圖，切換不同月份時圖表資料隨之更新，無收入時顯示適當的空白提示。

**Acceptance Scenarios**:

1. **Given** 當月有多筆不同分類的收入交易，**When** 使用者進入儀表板，**Then** 顯示收入分類圓餅圖，每個扇區對應一個父分類，大小與金額成正比。
2. **Given** 當月沒有任何收入交易，**When** 使用者進入儀表板，**Then** 收入分類圓餅圖區域顯示「本月無收入記錄」提示，不渲染空白圓餅圖。
3. **Given** 使用者正在查看某個月份，**When** 點擊月份切換器切換到不同月份，**Then** 收入分類圓餅圖的資料同步更新，與支出圓餅圖保持一致的月份。

---

### User Story 2 — 查看收入分類前 5 名排行 (Priority: P2)

圓餅圖下方顯示收入分類金額排行前 5 名的列表，包含分類名稱、金額與百分比，讓使用者不需要互動就能快速讀取數字。

**Why this priority**: 圓餅圖適合看佔比，但讀取精確數字較困難；排行列表補充了圖表的不足，提升資訊密度。

**Independent Test**: 即使不看圓餅圖，也能從列表中讀到「第 1 名是薪資，NT$50,000，佔 80%」等資訊。

**Acceptance Scenarios**:

1. **Given** 當月有 3 個以上的收入分類，**When** 使用者查看收入圓餅圖，**Then** 圖表下方顯示前 5 名列表，包含排名、分類名稱、金額與百分比。
2. **Given** 當月只有 2 個收入分類，**When** 使用者查看收入圓餅圖，**Then** 列表僅顯示 2 筆，不補空白項目。

---

### User Story 3 — 雙圓餅圖模式查看子分類細節 (Priority: P3)

使用者可透過「雙圓餅圖」開關，將收入分類圓餅圖切換為父分類（內圈）+ 子分類（外圈）的雙環模式，查看更細緻的收入來源明細。

**Why this priority**: 對有細分收入來源的使用者（如多個兼職項目）有用，但非所有人必需，為進階功能。

**Independent Test**: 勾選「雙圓餅圖」後，圖表切換為雙環顯示，取消勾選後恢復單環；頁面重新整理後，偏好設定保留。

**Acceptance Scenarios**:

1. **Given** 使用者勾選收入圓餅圖旁的「雙圓餅圖」開關，**When** 圖表重繪，**Then** 顯示內圈（父分類）+ 外圈（子分類）的雙環圓餅圖。
2. **Given** 使用者啟用了雙圓餅圖模式，**When** 重新整理頁面，**Then** 模式設定透過 localStorage 保留，圖表直接以雙環模式顯示。

---

### Edge Cases

- 當月所有收入皆歸屬於同一個分類時，圓餅圖顯示單一扇區（整圓），不報錯。
- 收入分類被刪除但仍有歷史交易時，以「（未知分類）」顯示，不因此崩潰。
- 使用者帳號從未新增任何收入交易時，圖表區域顯示空白提示，不報錯。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 儀表板 MUST 新增一張「收入分類」圓餅圖卡片，位於支出分類與資產配置卡片之間。桌面 2 欄格線下，排列為：第一列（預算進度 ＋ 支出分類）、第二列（收入分類 ＋ 資產配置）、第三列（近期交易全寬），格線欄數維持不變。
- **FR-002**: 收入分類圓餅圖 MUST 顯示當月（與月份切換器同步）各父分類的收入金額佔比。
- **FR-003**: 圓餅圖資料來源 MUST 僅包含 `type = 'income'` 且未被排除統計的交易。
- **FR-004**: 圓餅圖下方 MUST 顯示收入分類金額排行前 5 名（含分類名稱、金額、百分比）。
- **FR-005**: 當月無收入交易時，圖表區域 MUST 顯示「本月無收入記錄」文字提示，不渲染空圓餅。
- **FR-006**: 使用者 MUST 能透過「雙圓餅圖」開關，在單環（父分類）與雙環（父 + 子分類）模式之間切換。
- **FR-007**: 雙圓餅圖偏好設定 MUST 透過 localStorage 保留，重整頁面後恢復上次的選擇。
- **FR-008**: 收入分類圓餅圖的月份 MUST 與儀表板月份切換器完全同步，切換月份時資料隨之更新。
- **FR-009**: 使用者點擊收入分類圓餅圖的扇區後，MUST 跳轉至對應收入分類的當月交易列表（篩選條件：該父分類、type=income、當月日期範圍），行為與支出圓餅圖完全一致。

### Key Entities

- **收入分類圓餅圖資料**: 當月所有收入交易，依父分類聚合後的金額合計，結構與現有支出分類資料（`catBreakdown`）相同，包含父分類名稱、顏色、金額，以及可選的子分類明細。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者進入儀表板後，在不需要點擊任何按鈕的情況下，即可看到當月收入的分類圓餅圖。
- **SC-002**: 切換月份後，收入圓餅圖資料在 1 秒內完成更新（與支出圓餅圖同步）。
- **SC-003**: 雙圓餅圖模式的切換操作在 0.5 秒內完成視覺更新。
- **SC-004**: 有收入記錄的月份，100% 的收入交易皆正確反映在圓餅圖中（無遺漏、無重複計算）。

## Clarifications

- Q: 儀表板卡片版面位置？ → A: 收入分類圓餅圖卡片插入於支出分類與資產配置之間，格線維持 2 欄不變。桌面排列：第一列（預算進度 ＋ 支出分類）、第二列（收入分類 ＋ 資產配置）、第三列（近期交易全寬）。

## Assumptions

- 收入分類的資料結構（父子兩層）與支出分類完全一致，可共用相同的聚合邏輯。
- 收入分類圓餅圖的色彩生成邏輯與支出圓餅圖相同，不需要額外的色彩規則。
- 儀表板版面在新增收入圓餅圖卡片後需調整格線配置，行動裝置單欄版面維持不變。
- 不新增任何新的後端 API 端點；收入分類資料由現有儀表板 API 擴充回傳。
